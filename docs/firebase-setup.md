# Firebase 설정 안내 (실시간 공유 기능 켜기)

PBS 행동 관찰 기록장의 "여러 기기에서 함께 쓰기"는 Firebase의 **Firestore**(자료 저장)와 **Authentication**(구글 로그인)을 씁니다.
무료 요금제(**Spark**) 안에서만 동작하도록 만들었고, Storage·Cloud Functions는 쓰지 않습니다(녹음·사진·PDF는 올라가지 않습니다).

아래 순서대로 한 번만 설정하면 됩니다. 화면 이름은 2026년 11월 기준 한국어 콘솔 이름입니다(영어 화면이면 괄호 안 이름).

## 1. 프로젝트 만들기
1. <https://console.firebase.google.com> 에 구글 계정으로 들어갑니다.
2. **프로젝트 만들기**(Create a project)를 누르고 이름을 정합니다(예: `pbs-capstone`).
3. "Google 애널리틱스 사용 설정"은 꺼도 됩니다.
4. 만든 뒤 왼쪽 아래 요금제가 **Spark(무료)** 인지 확인합니다. Blaze로 바꾸라는 안내가 나와도 바꾸지 마세요.

## 2. Firestore 데이터베이스 만들기
1. 왼쪽 메뉴 **빌드**(Build) → **Firestore Database** → **데이터베이스 만들기**(Create database).
2. 위치(Location): **asia-northeast3 (Seoul)** 를 고릅니다.
   - ⚠ 위치는 한 번 정하면 **바꿀 수 없습니다.** 꼭 서울을 고르세요.
3. 보안 규칙 시작 방식: **프로덕션 모드**(Start in production mode) → 만들기.

## 3. 구글 로그인 켜기
1. **빌드** → **Authentication** → **시작하기**(Get started).
2. **로그인 방법**(Sign-in method) 탭 → **Google** → **사용 설정**(Enable) 켜기.
3. "프로젝트 지원 이메일"에 본인 이메일을 고르고 **저장**.

## 4. 승인된 도메인 추가
1. **Authentication** → **설정**(Settings) 탭 → **승인된 도메인**(Authorized domains).
2. **도메인 추가** → `ij17838-creator.github.io` 입력 → 추가.
   - `localhost`는 기본으로 들어 있습니다(내 컴퓨터에서 시험할 때 씀).

## 5. 웹 앱 등록하고 설정값 받기
1. 왼쪽 위 톱니바퀴 → **프로젝트 설정**(Project settings) → **일반**(General) 탭 아래 **내 앱**(Your apps).
2. **웹** 아이콘(`</>`)을 누르고 앱 닉네임(예: `pbs-web`)을 적은 뒤 **앱 등록**. "Firebase 호스팅 설정"은 체크하지 않습니다.
3. 화면에 나오는 `const firebaseConfig = { apiKey: "...", authDomain: "...", projectId: "...", ... };` 부분을 복사합니다.
4. 이 값을 Claude에게 전달하거나, 직접 `index.html`에서 다음 줄을 찾아 `{}` 안에 붙여 넣습니다.
   ```js
   const FIREBASE_CONFIG={};
   ```
   예: `const FIREBASE_CONFIG={apiKey:"AIza...",authDomain:"pbs-capstone.firebaseapp.com",projectId:"pbs-capstone",storageBucket:"...",messagingSenderId:"...",appId:"..."};`
   - 이 값은 공개돼도 되는 값입니다(접근은 아래 보안 규칙과 로그인으로 막습니다).
   - 비워 두면 공유 기능 버튼이 숨겨지고 지금처럼 이 기기에만 저장됩니다.

## 6. 보안 규칙 게시
1. **Firestore Database** → **규칙**(Rules) 탭.
2. 저장소의 [`firestore.rules`](../firestore.rules) 파일 내용을 전부 복사해 편집창의 내용을 **모두 바꿔** 붙여 넣습니다.
3. **게시**(Publish)를 누릅니다.
   - 이 규칙은 로그인한 사람 중 그 프로젝트의 멤버만 읽고 쓸 수 있게 하고, 수정 기록은 고치거나 지울 수 없게 합니다.

## 7. (권장) 사용량 확인
- **Firestore Database** → **사용량**(Usage) 탭에서 하루 읽기·쓰기 횟수를 볼 수 있습니다.
- 무료 한도: 하루 **쓰기 2만 회 / 읽기 5만 회 / 삭제 2만 회**, 저장 1GiB. 한도를 넘으면 그날은 공유가 멈추고(요금이 나가지는 않음), 다음 날 다시 됩니다.
- 대략: 글 칸 하나를 고치면 4회 정도 쓰기, 공유 시작 때 프로젝트 크기만큼(예시 프로젝트 약 230회) 쓰기, 공유 프로젝트를 열 때 칸 수만큼 읽기가 듭니다.

## 설정 후 확인 순서 (실제 Firebase 연결 시험)
설정값을 넣은 `index.html`이 GitHub Pages에 올라간 뒤, 기기 두 대(또는 PC 브라우저 + 시크릿 창)로 확인합니다.

1. 기기 A: 프로젝트 열기 → "여러 기기에서 함께 쓰기" → **구글로 로그인** → 공유 코드(6자 이상) 입력 → **공유 시작**. 공유 ID가 나오는지 확인.
2. Firebase 콘솔 → Firestore → 데이터에 `projects`, `invites` 컬렉션이 생겼는지 확인.
3. 기기 B: 첫 화면 **공유 코드로 프로젝트 받기** → 틀린 코드 입력 → "맞지 않습니다" 안내 → 맞는 코드 입력 → 같은 프로젝트가 열리는지.
4. A에서 '표적행동 정의'의 행동 이름을 고치고 칸을 벗어남 → B 화면에 몇 초 안에 반영되는지, 칸 이름 옆에 "마지막 수정: 이름 · 시각"이 나오는지.
5. 두 기기에서 같은 '조작적 정의' 칸을 거의 동시에 다르게 고침 → 칸 옆 "다른 버전 1개"와 프로젝트 첫 화면 "확인할 충돌 1개"가 나오는지, 버튼 셋이 동작하는지.
6. B의 와이파이를 끄고 내용을 고침 → 화면 위 "오프라인 (보낼 변경 n개 대기)" → 와이파이를 켜면 A에 반영되는지.
7. A(소유자)에서 B를 **내보내기** → B 화면 위에 "공유에서 빠짐"이 나오는지.
8. 콘솔 → Firestore → 사용량에서 쓰기 횟수가 예상 범위인지.

문제가 생기면 브라우저 화면의 안내 문구와 함께 Claude에게 알려 주세요.
